# Development Guide

## Prerequisites

- [Node.js](https://nodejs.org/) >= 18
- [Rust](https://www.rust-lang.org/tools/install) >= 1.77
- Tauri system dependencies → [tauri.app/start/prerequisites](https://tauri.app/start/prerequisites/)
  - **Windows**: Microsoft C++ Build Tools + WebView2
  - **macOS**: Xcode Command Line Tools
  - **Linux**: `libwebkit2gtk-4.1`, `libssl-dev`, `libayatana-appindicator3-dev`, etc.

---

## Running Locally

```bash
npm install
npm run tauri dev
```

This starts the Vite dev server (port 1420) and the Tauri native window simultaneously. Hot-reload applies to frontend changes; Rust changes require Cargo recompilation.

---

## Build for Production

```bash
npm run tauri build
```

Outputs installers to `src-tauri/target/release/bundle/`:

| Platform | Format |
|----------|--------|
| Windows | `.msi`, `.exe` (NSIS) |
| macOS | `.dmg`, `.tar.gz` |
| Linux | `.deb`, `.rpm`, `.AppImage` |

## Adding a New Tauri Command

1. **Define the handler** in `src-tauri/src/commands.rs`:
   ```rust
   #[tauri::command]
   pub async fn my_command(state: State<'_, AppState>, arg: String) -> CmdResult<String> {
       // ...
       Ok(result)
   }
   ```

2. **Register it** in `src-tauri/src/lib.rs` inside `invoke_handler![]`:
   ```rust
   commands::my_command,
   ```

3. **Call it from the frontend** via Pinia store or component:
   ```typescript
   import { invoke } from '@tauri-apps/api/core'
   const result = await invoke<string>('my_command', { arg: 'value' })
   ```

---

## Adding a New Tauri Event (backend → frontend)

1. **Emit from Rust** (typically inside `ssh.rs` or a command):
   ```rust
   app.emit("my_event_name", payload)?;
   ```

2. **Listen in Vue component**:
   ```typescript
   import { listen } from '@tauri-apps/api/event'
   const unlisten = await listen<PayloadType>('my_event_name', (event) => {
     console.log(event.payload)
   })
   // Clean up in onBeforeUnmount:
   onBeforeUnmount(() => unlisten())
   ```

## Database Changes

`db.rs` uses runtime `sqlx::query` / `query_scalar`; it does not require `DATABASE_URL` or a `.sqlx/` cache to compile. The SQLite database is `{app_data_dir}/sessions.db` and remains the default when no storage settings file exists.

Storage changes must keep these modules aligned:

- `storage.rs`: shared async CRUD and empty-target import contract
- `db.rs`: SQLite schema and transactional import
- `yaml_storage.rs`: schema v1, safe subset, validation, recovery backup, atomic write
- `storage_manager.rs`: selection settings, target validation, verified copy, and switch
- `commands.rs` / `lib.rs`: Tauri command registration
- `src/types` / `src/stores` / settings and session components: frontend IPC contract

Use only temporary fixture paths in tests. Do not connect to an external SSH host or read real credentials. The Rust suite covers both CRUD contracts, restart, corruption, atomic/backup failures, concurrent YAML writes, copy in both directions, non-empty target refusal, and settings-commit rollback.

## Project Conventions

- All Tauri commands return `Result<T, String>` aliased as `CmdResult<T>`; errors are stringified via the `to_str` helper.
- Frontend errors from `invoke()` are caught at the call site and displayed with `useMessage().error(...)`.
- Terminal IDs are UUIDs generated by the Rust backend at connection time; they are the key linking `TerminalTab`, `TerminalMap`, and Tauri event names.
- Session grouping is purely derived (computed from `group_name` field); there is no separate groups table.
